Design philosophy

the one rule

The AI is a second brain that helps think, not a chatbot that answers. Every interaction should feel like a capable colleague sitting beside you — pointing at a sticky, scratching one out, drawing a line between two ideas — not like a Q&A widget.

This has implications for everything else:

  • AI surfaces are inline. Ghost stickies, critique bubbles, connection lines, margin notes — all live on the same canvas as user ideas, not in a side panel.
  • AI output is draftable. Everything the AI produces is dismissible, editable, draggable, or promotable. Nothing is final until the human commits.
  • AI is visibly thinking. The "thinking beat" (candidates appear, get rejected, survivors solidify) is explicit. Hidden reasoning is untrustworthy reasoning.
  • The canvas is the source of truth. The turn log is a history view, not a parallel store. Transferring a log entry creates a new sticky on the canvas.

Two visual themes, one system

The prototype ships two interchangeable aesthetics backed by the same tokens:

  • sketch — warm paper, hand-drawn ink, torn-paper stickies, Kalam font. Evokes moleskine or a whiteboard in a dimly-lit room.
  • whiteboard — cool cream board, marker-style strokes, translucent colour blocks, cleaner geometry.

Users switch via the Tweaks panel. Every component must render correctly under body.theme-sketch and body.theme-whiteboard.

State model

The canvas keeps one authoritative list of ideas and connections in its own state. Everything else is a view or an overlay.

CanvasScreen {
  ideas             : Idea[]         // merge of seeded + user-added + AI-committed
  userConnections   : Connection[]   // user-drawn
  deletedKeys       : string[]       // tombstones for deleted built-in connections
  selectedId        : IdeaId | null
  linkMode          : boolean        // "draw connection" mode
  linkSource        : IdeaId | null  // first sticky picked
  thinkingIdeas     : Candidate[]    // live during "thinking beat"
  aiThinking        : boolean        // locks nudge button
  dismissedCritiques: string[]
  dismissedGhosts   : string[]
  acceptedGhosts    : Idea[]
}

Effective visible set (pure function)

const visibleConnections =
  [...CONNECTIONS, ...userConnections]
    .filter(c => !deletedKeys.includes(connKey(c)));

const visibleCritiques =
  CRITIQUES.filter(c => !dismissedCritiques.includes(c.id));

const visibleGhosts =
  GHOSTS.filter(g => !dismissedGhosts.includes(g.id));
why This pattern keeps AI output trivially reversible. A dismissed critique is a tombstone, not a mutation — undo is just popping the array.

LLM integration

The prototype uses local deterministic data. For production, replace the data layer with a call per "beat". Every LLM call is scoped to a single beat — never a general chat.

The five beats that call the LLM

beattriggerresponse shape
scout user idle 2s with ≥3 ideas, or "nudge me"Candidate[] (see §07)
connect on every new idea, after debounceConnection[]
critique idea stable 5s & not already critiquedCritique
cluster ≥5 ideas with ≥3 shared_theme connectionsClusterHint
summarise manual — "one-line takeaway" buttonstring

Contract: request envelope

Every call to the LLM goes through one helper, callBeat(name, context). Context is always the current board state, serialised minimally:

type BeatContext = {
  beat: "scout"|"connect"|"critique"|"cluster"|"summarise";
  board: {
    title: string;
    ideas: { id: string; title: string; body?: string; killed?: boolean }[];
    connections: { from: string; to: string; kind: string }[];
  };
  focusId?: string;              // which idea the beat is about, if any
  aggressiveness: "gentle"|"balanced"|"aggressive";
  turnsUsed: number;             // respect per-beat token budgets
};

Contract: response

The LLM must return strict JSON matching the beat's schema. Any free text is an error — wrap it in the appropriate field.

// scout response
{
  "candidates": [
    { "title": "Decision journal → auto-surface precedent",
      "rationale": "Past decisions are the training data.",
      "color": "blue",
      "confidence": 0.78 },
    // … up to 5
  ]
}

Client-side filter

Before committing any AI output to the canvas, run it through scoreCandidate(). Drop anything below the aggressiveness threshold. This is the "thinking beat" you see visually — the client decides which candidates survive, so the visual animation reflects real filtering, not just choreography.

const thresholds = {
  gentle:     0.75,   // only the confident stuff
  balanced:   0.55,
  aggressive: 0.30,   // show almost everything
};
const survivors = candidates.filter(c => c.confidence >= thresholds[mode]);

Prompt contracts

System prompt (persona — keep short)

You are Dev, a staff-level engineering manager pair-thinking
with a colleague on a brainstorm board.

Tone: concise, pragmatic, a little dry. Never upbeat-cheerful.
Never sycophantic. Never say "great idea".

You do not have opinions until asked. You do not summarise.
You scout, connect, critique, cluster, summarise — exactly one
at a time. Return valid JSON only.

Per-beat prompts

scout

Given the board state, propose 3–5 adjacent ideas the
colleague might have missed. For each:
  - title: ≤ 9 words, no period
  - rationale: ≤ 16 words, why this follows
  - color: pick from {blue, green, peach, lilac, pink}
  - confidence: 0.0–1.0 of how relevant you believe it is

Return { "candidates": [...] }. Nothing else.

connect

Return only connections that are NOT already in the board.
For each, pick exactly one kind from:
  builds_on     — A strictly extends or implements B
  contradicts   — A negates B's premise
  shared_theme  — both orbit the same abstraction, weakly
  revives_killed — A makes a previously killed B viable again

Give a ≤ 10-word rationale.

Return { "connections": [...] }. Empty array is a valid answer.

critique

Critique the focus idea ONLY — not the board.
Pick the single sharpest angle (devil's advocate, NOT cheerleader).
Max 22 words. End with a question OR a "you're assuming…" frame.

Return { "text": "...", "strength": 0–1 }.
pro-tip Use response_format: { type: "json_schema" } on the API call and pass the matching schema. Any time the model free-forms text, reject the entire response — don't parse.

Interaction beats

The UI reveals AI output over time. These choreographies are not decoration — they give the user a chance to interrupt and make the AI feel like it's thinking, not answering.

Thinking beat (scout)

  1. Persona dock: avatar starts pulsing, thinking=true shows sliding bar. Line changes to "Drafting a few candidates."
  2. Candidates enter one-by-one (stagger 280ms) near the focus idea. CSS class .thinking-candidate.
  3. After all revealed, rejections scratch out with ink strokes (class .thinking-reject) one by one (420ms each).
  4. Survivors pulse blue (.thinking-survive) then commit as real Idea entries with ai: true.
  5. Persona bar hides, thinking=false.

Connection beat

  1. AI returns Connection[]; ConnectionLayer animates them in with draw-line 700ms per path, staggered 120ms.
  2. Hover any line → mid-point × button appears for deletion (class .hover-delete). User can also delete kills the tombstone so it doesn't come back.
  3. User can draw their own: toolbar link button → rubber-band line → click two stickies → new Connection with kind: "builds_on".

Critique beat

  1. AI returns one critique; it fades in as a CritiqueBubble or MarginNote anchored to the focus idea.
  2. User can drag critique anywhere on the board (persistent position).
  3. User dismisses → tombstoned into dismissedCritiques. Same critique can't be re-suggested for 90s.

type Turn = {
  id: string;
  ideaId: string;
  at: number;                  // unix ms
  origin: "ai"|"user"|"edit"|"critique";
  text: string;
  rationale?: string;         // only for ai-origin
  pinned?: boolean;

};

Accessibility

  • All draggable elements must be keyboard-reachable. Provide arrow-key nudging as a fallback.
  • Connection × delete control must have a text equivalent in the right-click menu for each sticky.
  • AI thinking bar must not be the only indicator — pair with text ("drafting…").
  • Colour-only distinction of connection kinds fails WCAG. Include the kind as a tooltip and in the connection's micro-label on hover.
  • prefers-reduced-motion: shorten thinking beat to 400ms total, skip scratch-out animation.

Handoff checklist

ship-gate — do

  • All 5 beats wired to real LLM with JSON schema validation
  • Client-side confidence filter matches aggressiveness setting
  • Tweaks panel persists to IndexedDB, not localStorage
  • Both theme-sketch and theme-whiteboard tested
  • Prefers-reduced-motion respected for thinking beat
  • Every AI output is tombstone-removable, not hard-deleted
  • Turn log drag-to-transfer creates a real new idea

ship-gate — don't

  • Don't add a sidebar chat. The persona dock is the chat.
  • Don't let the AI call more than one beat per user event
  • Don't summarise the board without user asking — it breaks trust
  • Don't auto-commit AI candidates — they go through the thinking beat
  • Don't let critique tone become upbeat; keep it devil's-advocate
  • Don't use emoji in persona lines — plain prose only
