00Mental model

Brainstorm is not a whiteboard tool with AI bolted on. It is a thinking workshop in which AI personas are first-class participants. Three rules govern the whole system:

  1. The board is the source of truth. Every other surface — inspector, brief, log, handoff — is a projection of board state. Editing a projection edits the board.
  2. AI suggests; the user confirms. Nothing the AI proposes lands on the board until the user accepts (or auto-accept is explicitly turned on per persona). Every AI move is reversible and attributed.
  3. Phases are descriptive, not gating. An idea moves through 8 phases (frame → diverge → cluster → critique → brief → review → handoff → archive). The system suggests the next phase but never blocks the user from skipping or returning.
If you only remember one thing Treat AI like a junior collaborator who leaves margin notes in pencil. The user is always the one who picks up the pen.

01Core data model

The whole product is a graph of these eight entities. Anything not derivable from them is an implementation accident.

Project

The top-level container — a workspace with shared autonomy settings, persona roster, and N boards.

Project {
  id, title, owner, members[],
  // global controls
  autonomyDial: "silent" | "suggestive" | "active" | "takes-pen",
  personaRoster: PersonaId[],   // who can be in the room
  principles: IdeaId[],         // ideas promoted from boards (see §03)
  createdAt, updatedAt
}

Board

One thinking project. Every idea, sticky, and line lives on exactly one board (or, for principles, multiple).

Board {
  id, projectId, title, summary?,
  status: "active" | "paused" | "archived",
  currentPhase: 1..8,
  ideas: IdeaId[],
  connections: ConnectionId[],
  clusters: ClusterId[],
  activePersonas: PersonaId[],  // override of project roster
  lastActivityAt, openedBy
}

Idea (the sticky)

The atomic unit. An idea is what users put on the board and what graduates into a brief.

Idea {
  id, boardId, position: {x, y}, color: StickyColor,
  title, body?,
  phase: 1..8,                 // per-idea phase, can lag board
  authorRef: { kind: "user" | "persona", id },
  tags: string[],
  contradictions: IdeaId[],         // reverse-indexed for speed
  parentIdeaId?: IdeaId,            // for child ideas / forks
  pinnedToBoardIds: BoardId[],      // for cross-board ideas / principles
  state: "draft" | "live" | "settled" | "muted",
  createdAt, updatedAt
}

Connection (the line)

A typed, directed edge between two ideas. Lines are first-class — they have authors, confidence, and history. Screen 05 inspects these.

Connection {
  id, boardId, from: IdeaId, to: IdeaId,
  type: "parent-of" | "shares-theme" | "contradicts" | "depends-on" | "evidence-for",
  authorRef: { kind, id },
  confidence: 0..1,            // AI-drawn lines come with this
  reasoning?: string,               // why drawn — shown in inspector
  createdAt, supersededBy?: ConnectionId
}

Cluster

A named grouping of ideas. Can be AI-proposed or user-drawn. Visible only on Screen 02.

Cluster {
  id, boardId, label, ideaIds: IdeaId[],
  source: "ai" | "user-lasso",
  confidence?: 0..1,
  haloColor: "revive" | "ghost" | "ai" | "ink",
  state: "proposed" | "accepted" | "dismissed"
}

Persona

An AI participant with a fixed role. Built-ins: Scout, Synthesizer, Devil's Advocate, Historian. Users can spawn custom personas per board.

Persona {
  id, name, role: "challenger" | "synthesizer" | "advocate" | "historian" | "custom",
  bio: string, avatarColor,
  active: boolean,
  scope: "project" | "board",    // custom personas are usually board-scoped
  costPerTurn?: number,
  interruptPolicy: "never" | "on-demand" | "auto-on-trigger"
}

LogEvent

The append-only history of everything that happened on a board. Powers Screen 06's scrubber.

LogEvent {
  id, boardId, ts,
  kind: "idea-created" | "idea-edited" | "connection-drawn" | "cluster-proposed" | "phase-advanced" | "ai-nudge" | "persona-toggled" | ...,
  authorRef: { kind, id },
  payload: JSON,                // kind-specific
  reversed: boolean
}

Brief

The output document an idea graduates to in phase 5+. Sections are computed from the idea + its connected children + its log.

Brief {
  id, ideaId, version,
  sections: { problem, approach, mustStayTrue, risks, openQuestions, ... },
  marginNotes: { sectionId, personaId, body, ts }[],
  status: "draft" | "ready-for-review" | "shipped"
}

03The eight screens

For each: purpose, entry/exit, layout regions, key interactions, AI hooks, edge cases. Visual reference: Screen Map.html.

01
Always-visited entry · the project's home base

Multi-board home

A tiled view of all boards in the project, ordered by recent activity, with AI digests on what changed while you were away.

P1

Entry

  • App launch (default route).
  • Logo click from any other screen.
  • Deep link /p/:projectId.

Layout regions

  • Header pill · project name + member count + + new board button.
  • Active row · boards with activity in last 7d. Sort by lastActivityAt desc.
  • Archive drawer · boards with status === "archived". Collapsed by default.
  • Search bar · persistent top-right; opens <CrossBoardSearch> overlay (queries idea titles, tags, brief sections).

Key interactions

click board → route to /b/:boardId (Screen 02 default zoom)
hover board → reveal "open · archive · duplicate" actions
drag board between rows → change status
click + new board → empty-state: "What are you trying to figure out?" — single textarea, AI seeds first 3 stickies on submit

AI hooks

  • If a board has activity since user's last visit, render a <NudgeCard> over its thumbnail summarizing what changed (e.g. "3 new connections, 1 contradiction").
  • If user hasn't opened a board in 14d, propose archive.

Edge cases

  • Zero boards — the whole canvas becomes the new-board prompt. No empty grid.
  • Shared boards from other projects — separate "Shared with you" section under archive.

Exit

Click any board → Screen 02. Search result click → Screen 02 with the matching idea pre-focused.

02
The board itself · the workhorse

Cluster view (board canvas)

The infinite-pan board with stickies, connection lines, and — critically — auto-grouping halos when zoomed out past 50%.

P1

Two zoom modes

This screen has one DOM, two visual modes, smoothly tweened by zoom level:

  • Zoom > 50% — sticky-level. Read text, draw lines, edit ideas. Halos render as faint backgrounds.
  • Zoom ≤ 50% — cluster-level. Stickies become 22×16 chips. Halos become bold; cluster labels become primary text. AI suggestions for cluster merges/splits appear here.

Layout regions

  • Top-left · phase strip (<PhaseStrip>) and breadcrumb back to home.
  • Top-right · zoom control + view toggle (stickies / clusters / map).
  • Right rail · active personas (<PersonaChip> stack) + idea search.
  • Bottom-left · the running <NudgeCard> queue from synthesizer/scout.
  • Bottom-center · <ConfirmBar> appears only when AI proposes a phase advance.

Key interactions

click sticky → open inspector in focus or bloom mode (already designed)
click line → open connection inspector
drag sticky → live update position; if dropped inside a halo, prompt to add to cluster
lasso (hold ⇧) → creates a user cluster; AI auto-suggests a name
double-click empty space → new sticky, focused for typing

AI hooks

  • Synthesizer proposes new clusters, merges, or splits via <NudgeCard>. accept writes to Cluster; preview shows ghost halos non-destructively.
  • Scout may propose reframing an idea — surfaces as a margin note on the relevant sticky.
  • Devil's Advocate auto-spawns when a sticky's body contains an unsupported claim (per autonomy dial). Drops a contradicts line as proposed.
Don't Don't auto-apply any AI move when autonomy is below "takes-pen". Render as proposed (dashed, 60% opacity) and require user confirm.

Exit

Click sticky → inspector overlay (modal-on-board). Click ↗ brief on an idea ≥ phase 5 → Screen 04. Click ↗ map → Screen 03. Click breadcrumb → Screen 01.

03
When ideas travel between boards

Cross-board map

A galaxy view: every board is a planet, sized by activity. Edges between boards mean shared ideas — same Idea.id pinned to multiple boards, or AI-detected theme overlap.

P2

Entry

  • Top-right view toggle on Screen 02.
  • Project menu → "Map".

Layout regions

  • Canvas · force-directed layout of BoardThumbnail as planets.
  • Edges · two kinds:
    • Solid (purple) — explicit pinned idea (Idea.pinnedToBoardIds.length > 1).
    • Dashed (green) — AI-detected theme overlap, with confidence.
  • Right rail · principles drawer — ideas the user has promoted to Project.principles.

Key interactions

click planet → route to Screen 02 for that board
click edge → popover lists shared ideas; jump to either side
Synthesizer nudge: "X appears on 3 boards — promote to principle?" → on accept, idea moves to project-level principles[] and gains a ★ badge everywhere it appears

AI hooks

  • Background job recomputes theme overlaps after any board update.
  • The "promote to principle" nudge fires when an idea (or paraphrase) appears on ≥ 3 boards.

Exit

Click planet → 02. Click principle → opens it as an inspector overlay over home.

04
Output surface · phase 5+

The Brief

An idea that has reached phase 5 graduates from sticky to document. The brief is computed from the idea + its child ideas + its log; it's editable in place; AI keeps leaving margin notes.

P1

Entry

  • Click ↗ brief on a sticky in phase ≥ 5.
  • Inspector "graduate to brief" action (auto-fires the first time an idea hits phase 5).

Layout regions

  • Header · brief title (= idea title) + phase strip + version pill.
  • Document body · sections in a fixed order (Problem · Approach · Must stay true · Risks · Open questions). Each section is editable contenteditable text.
  • Right margin · AI margin notes (Brief.marginNotes) — sticky-styled, 90px wide, persona-attributed.
  • Footer · "send to handoff" + "back to board" + version dropdown.

Computed sections

SectionComputed from
ProblemPhase-1 frame sticky body + any user edits
ApproachThe idea body + its highest-confidence parent-of children
Must stay trueStickies tagged constraint in the idea's connected subgraph
RisksConnections of type contradicts + Devil's Advocate notes
Open questionsStickies in state: "draft" attached as children

Key interactions

edit any section text → writes back to source sticky; show inline "edit on board too" highlight for 3s
click margin note → jump to source sticky on board
⌘ S → snapshot current text into Brief.versions[]

AI hooks

  • Whenever the brief is opened, run all active personas with brief-context-aware prompts. New margin notes append to the right rail with persona color.
  • Scout asks for citations on unsupported claims.
  • Historian flags ambiguous terms (links to glossary).

Edge cases

  • If a source sticky is deleted while the brief is open, mark the affected section "orphan — reattach or delete" — never silently drop content.
  • Briefs are versioned. Editing an old version forks a new one.

Exit

Footer → handoff or board.

05
Click on a line · the lines have stories

Connection inspector (popover)

Not a full screen — a popover that opens at click point. Shows who drew the line, why, with what confidence, and lets the user flip the type, edit reasoning, or delete.

P2

Entry

Single click on any <ConnectionLine> on Screen 02 (sticky-level zoom only).

Layout

  • Header · type pill + glyph + "from → to" idea titles.
  • Body · reasoning string, confidence meter, "show on board" mini map.
  • Author row · persona avatar + name + relative time.
  • Actions · flip type · show reasoning · ↶ delete

Key interactions

flip type → dropdown of all 5 types; on change, log a new Connection with supersededBy back-pointing
delete → soft-delete with 5s undo toast (don't actually drop the row — set state: "deleted" for log replay)
while popover is open, the rest of the board dims to 30% opacity to focus the line

AI hooks

  • "Show reasoning" expands the AI's chain-of-thought for why this line was drawn (only for AI-authored connections).
  • If user changes type, AI may post a counter-nudge ("are you sure? these contradict in 2 places") — also dismissible.

Exit

Click outside popover, esc, or any action button.

06
Replay · audit · trust

Project log + scrubber

An append-only feed of every move on the board, with a timeline scrubber that re-renders the board to past state. Foundational for trust ("did the AI just do that?") and undo.

P2

Entry

  • Right rail icon on Screen 02 (clock).
  • Keyboard ⌘ K.

Layout

  • Filter row · pills: all · AI only · my edits · connections · contradictions.
  • Event list · vertical timeline, newest first. Each event has dot color by author kind, time, action sentence with bolded entities, and a ↶ rewind to here hover action.
  • Bottom scrubber · play/pause + draggable knob + relative-time label.

Key interactions

drag knob → board on Screen 02 (peek-rendered) replays state at that ts
release knob OR click fork from here → creates a branch board (copy with truncated log)
click event → jump board view to the affected idea, highlight it briefly
↶ rewind to here → rolls log forward as reversed events; original log preserved

Edge cases

  • Events are immutable. Undo creates a new event of kind reverse-of.
  • Forking from history doesn't fork live AI conversations — those start fresh on the new branch.
07
Phase 8 · ship the brief

Handoff

A small panel of integration channels (GitHub, Slack, Linear, Notion). Each channel auto-formats the brief for that medium. Preview before ship; ship is a one-click action that records a Handoff event.

P3

Entry

Footer button on Screen 04: send to handoff →.

Layout

  • Each channel card shows: icon, name, formatted preview, "ship" or "preview" button.
  • Channels selected here are independent — one brief can ship to multiple destinations in one session.

Per-channel formatting

ChannelFormat
GitHub issueTitle = brief title. Body = sections as Markdown headings; "Must stay true" → checkboxes.
Slack postTL;DR (≤ 3 sentences) + link back to brief. Posts to a target channel chosen here.
Linear ticketBrief mapped to ticket fields; "Risks" → labels; checks for owner/estimate and warns if missing.
Notion docFull brief preserved including margin notes as Notion comments.

AI hooks

  • Pre-flight check: AI flags missing fields per channel (no owner, no estimate, etc).
  • Post-ship: a handoff-confirmed event lands on the log; brief moves to status: "shipped".

Edge cases

  • If a channel isn't connected, the card shows a "connect" CTA inline; don't open a separate settings page.
  • "Ship" is idempotent: re-shipping updates the existing destination if found, doesn't duplicate.
08
Control panel · who's in the room

Persona panel

One autonomy dial + persona toggles + the "spawn custom persona" affordance. Lives in the right rail of Screen 02 (collapsed) and as a settings page (expanded).

P2

Autonomy dial

4 stops. Behavioral contract:

StopWhat changes
silentNo nudges. Personas only respond when @-summoned.
suggestiveNudges appear in queue; never auto-dismiss; never auto-apply.
active (default)Devil's auto-spawns counters; Synthesizer auto-clusters; user still confirms.
takes-penSome moves auto-apply (clustering, line drawing) with toast + undo. Phase advances still require <ConfirmBar>.

Persona row anatomy

  • Avatar (color = persona color), name, role, toggle.
  • Hover → bio + recent actions count.
  • Click name → opens persona detail (bio, prompt, cost, scope).

Spawning a custom persona

"+ custom persona" → form: name, one-sentence bio, tone, scope (this board / project)
submit → AI suggests a system prompt; user can edit; persona joins active roster

Edge cases

  • Cost cap per persona is enforced at the run loop; exceeding it pauses the persona with a toast, never silently.
  • Custom personas with scope: "board" are listed under their board only and don't survive board archive.

04Cross-cutting flows

The idea lifecycle

An idea moves through 8 phases. Each phase change emits a phase-advanced log event and may unlock surfaces (briefs become available at 5; handoff at 8).

1. frame      // "what are we trying to figure out?"
2. diverge    // generate options, no judgment yet
3. cluster    // group similar ideas (Screen 02 shines)
4. critique   // Devil's gets loud; counter-evidence
5. brief      // Screen 04 unlocks; idea graduates
6. review     // share for comment; margin notes accumulate
7. handoff    // Screen 07; ship to integrations
8. archive    // idea is done; remains queryable, log preserved

The AI nudge protocol

Every AI move follows the same shape:

  1. AI produces a NudgeProposal with kind (cluster, line, sticky, phase, brief-edit), payload, reasoning.
  2. System creates a LogEvent with kind: "ai-nudge" and renders a <NudgeCard> in the relevant queue.
  3. On user accept → apply payload, mark log event resolved, emit a follow-up event.
  4. On dismiss → mark resolved: false, hide card. Don't ask again for the same proposal in the same session.
  5. On preview → render the change as ghost (60% opacity, dashed) without writing; click again to accept.

Persistence & undo

  • Append-only log is the source of truth. Board state is a fold over the log.
  • Every destructive action ("delete sticky", "delete connection") is a soft-delete with 5s toast undo, then a real delete event.
  • The scrubber on Screen 06 replays by truncating the fold at a given ts; "fork from here" persists that fork as a new board.

05Build order & milestones

Build the data model first. Build screens in this order even if priorities suggest otherwise — each later screen depends on the data structures earlier screens force you to formalize.

M1 · Foundations (week 1–2)

  • Data model: Project, Board, Idea, Connection, LogEvent.
  • Append-only log + fold-to-state engine.
  • Shared primitives: <Sticky>, <ConnectionLine>, <NudgeCard>.

M2 · The board works (week 2–4)

  • Screen 02 sticky-level zoom (no clusters yet, no AI).
  • Screen 05 connection inspector — needed early to validate the line model.
  • Screen 06 log feed (no scrubber yet; just append-only feed).

M3 · AI joins the room (week 4–6)

  • Persona system + Screen 08.
  • Screen 02 cluster zoom + Synthesizer auto-clustering.
  • Nudge protocol fully wired.

M4 · Output & navigation (week 6–8)

  • Screen 01 multi-board home.
  • Screen 04 The Brief.
  • Screen 06 scrubber (rewind + fork).

M5 · System scale (week 8+)

  • Screen 03 cross-board map + principles.
  • Screen 07 handoff + first 2 integrations (GitHub, Notion).
  • Custom personas.

06Acceptance criteria

The system is "done" with each milestone when these are demonstrably true:

Trust

  • Every change to the board has a corresponding LogEvent with author and timestamp.
  • No AI move below takes-pen autonomy ever modifies state without an explicit user accept.
  • Every destructive action has a 5-second undo toast.

Coherence

  • Editing a sticky on the board updates the brief in real time, and vice-versa.
  • Persona color is consistent across every surface that mentions that persona.
  • Phase strip on board, brief, and log always agree.

Recoverability

  • Closing the tab and re-opening lands the user exactly where they left off (route + scroll + zoom).
  • Scrubber rewind followed by "back to now" perfectly restores the live state.
  • Forking from history yields a board whose log replays identically up to the fork point.

Discoverability

  • A user who has never seen Brainstorm can, given only Screen 01, reach a usable brief on Screen 04 in one session without help.
  • Every keyboard shortcut has a hover-discoverable equivalent.
North star When the user opens this product, they should feel like they've walked into their own studio — the boards are theirs, the AI is junior staff with margin pencils, and the user is always the one signing off. Build for that feeling, not for the feature list.
