Brainstorm system map · what's still missing

Eight screens to round out the system — plus where they slot in

The board + inspector handle one idea well. To make Brainstorm a place you live in, we still need: a home for many boards, a way to see clusters instead of stickies, a cross-board map for ideas that travel, an output surface when an idea is ready, a connection inspector for the lines between ideas, a project log for replay/audit, a handoff screen for shipping, and an autonomy panel for tuning the personas.

Priorities below — green = ship-blocking, blue = high value, purple = nice-to-have.
a note on what's there already Already designed: the board itself, the inspector (focus + bloom), clarification flow, integration guide. Not yet: everything outside one open idea — the navigation around it, the flow of many boards, the moments of output, and the controls that govern AI behaviour.

04
output surface · phase 5+

The Brief · idea graduates to a doc

P1 · ship-blocking
When an idea reaches phase 5, it earns a document view — readable, shareable, with AI margin notes still attached. Sections are auto-built from board state ("approach," "rules," "premortem risks"). You can keep editing live; AI commentary stays in the margin.
Day-1 freeze · brief
v3 · phase 5 of 8 · 18 turns · ready for review

Problem

New hires can't take their first action for >30 min on day 1. Tightened from "freeze". Affects ~70% of joiners, weeks 0–2.

Approach

Pair model: buddy week (Stripe-style, 5 days) plus sturdy runbook v2 as fallback. Both, not either.

Must stay true

  • Any new hire writes their first PR by Friday
  • Buddy must be ≤2y senior — peer pairing, not mentor
  • No new doc unless an existing one was first deleted

Risks (premortem)

  • If buddies are too busy, falls back to runbook → quality of runbook is load-bearing
  • If runbook drifts, Friday-PR still anchors action

Sequencing recommendation
Build the P1 trio first · Home → Cluster view → Brief.
Those three close the loop: a place to start, a way to see emerging structure, and a place where ideas graduate to output. Without them users can't justify the system as more than a single-board toy. The P2 set (cross-board map, connection inspector, log, persona panel) makes it feel cohesive. Handoff (P3) is last — the brief is editable enough that ad-hoc copy-paste covers it for v1.
